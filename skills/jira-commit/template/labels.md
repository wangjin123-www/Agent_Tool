# 工单标签表

`jira-commit` analyze 生成任务时，给每个任务打的标签一律从本表选取。**表外新词一律不打**（JIRA 的自由标签
一旦散开就无法收敛，本表就是唯一的收敛点）。

## 用词规则

1. **只选表内词**。表里找不到合适的 → **先往本表补一行新词（见规则 5），再用这个词**；
   不要打 `待归类`，也不要把表外词直接打进 JIRA。`待归类` 只作为"连新词都定不下来"的兜底。
2. **数量 ≤3**。优先选 1 个模块 + 1 个现象；判不出来就只打 1 个模块标签。
   本流程**不打 `已分析`**（那是缺陷分析子任务的专用标记，见文末「系统类」）。
3. **模块优先于现象**。能定位到具体模块（如 `电源管理`、`CAN通信`）就选模块；
   定位不到才退而选现象（如 `偶发难复现`）。
4. **标签不能含空格、逗号、分号**（JIRA 标签与回写解析都不允许）。
5. 想加新词：**用 Edit 工具往对应小节（模块类 / 现象类）补一行**，三列
   「标签 / 用途 / 典型触发关键词」都要填；补完再用这个词，并随本次变更一起提交本表。
   不要先把词打进 JIRA 再补表。

## 系统类

| 标签 | 用途 |
|---|---|
| `已分析` | **jira-commit 不打**。这是 `jira-ticket-analysis` 给缺陷分析子任务的专用标记（"本单已出分析结论"），保留在本表只为两边词表一致 |
| `待归类` | 兜底。仅当连"该补什么新词"都定不下来时才用（正常应先按规则 5 补词） |
