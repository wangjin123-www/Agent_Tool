# 终稿自检清单

> 盘问 100% 装配完成后、跑校验脚本之前过一遍。
> 脚本能查的（占位符残留 / 结构块缺失 / 长度）不用人工查；这里只列脚本查不出的。

## 内容质量

- [ ] **角色具体**：写出了领域 + 手段，不是「资深工程师」这种空词
- [ ] **任务单一**：一个 prompt 一件事；混了多件就拆成多个 prompt
- [ ] **禁止事项可执行**：「禁止引入动态内存」能判，「不要写烂代码」不能判
- [ ] **输出格式可预期**：说清了交付顺序和呈现形式，收到结果前就知道长什么样
- [ ] **上下文是查来的**：技术栈 / 文件名 / 数据结构都去工程里确认过，不是猜的
- [ ] **决策来源齐全**：盘问问答表每个决策都标了"用户选 X / 按推荐锁定"

## 忠于原意

- [ ] **没有替他加需求**：只把用户说的补全，没顺手加功能
- [ ] **没有替他做决定**：能定的自己定并声明；问过的按答复，没问过的不擅自改
- [ ] **没有改目标**：优化的是措辞和结构，用户要解决的问题没变

## 可验证性

- [ ] **有验证方式**：prompt 里说了怎么算做完（测试 / 编译 / 对比）
- [ ] **能独立完成**：执行者不用再来问一轮才知道要干什么

## 执行前

- [ ] 校验脚本退出码为 0
- [ ] `output/optimized-prompt.md` 是最终版（不是草稿）
- [ ] prompt **全文**贴给了用户，不是摘要
- [ ] 已进入执行（盘问即确认，不再二次征求）

## 常见返工原因

| 症状 | 原因 | 改法 |
|------|------|------|
| 执行者理解偏了 | 任务描述里混进了实现方案 | 任务只写「做什么」，方案留给执行者 |
| 产出风格不对 | 没引用项目里已有的同类文件 | 在「项目上下文」里写明参照文件路径 |
| 改动了不该改的 | 禁止事项没写或太虚 | 把「不许动的文件 / 不许引入的依赖」写死 |
| 交付物没法用 | 输出格式没交代 | 写清交付顺序 + 是否要完整代码 + 注释要求 |
