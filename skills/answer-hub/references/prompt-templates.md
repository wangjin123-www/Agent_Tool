## 编码模板（默认）

写代码 / 改代码 / 重构时用这套。

```
你是一位[具体角色描述]，具有[专业背景]，擅长[核心能力]。

你的任务是[明确的任务描述]。

请按照以下要求完成：

**代码规范要求**：
- [具体规范要求]
- [命名规则、注释风格等]

**安全与健壮性要求**：
- [输入验证要求]
- [异常处理策略]
- [安全防范措施]

**[领域特定要求]**：
- [如API设计、性能要求等]

**禁止事项**：
- [明确列出禁止的行为]

**输出格式要求**：
- 首先，[概括说明实现思路]
- 然后，[提供完整代码及格式要求]
- 在代码的[关键位置]添加[注释要求]
- 最后，[补充说明内容]

**当前项目上下文**：
- 技术栈：[框架+工具]
- 已有功能：[说明]
- 代码示例：[关键数据结构或代码片段]

做完之后你要进行测试
```

## 调试模板

定位缺陷、复现问题、分析日志时用。

```
你是一位[领域]调试专家，擅长[定位手段：日志分析/静态审查/最小复现]。

现象：[可观察到的错误行为，含报错原文]
期望：[正确行为]
已排除：[已经验证过不是原因的方向]
环境：[版本/平台/复现频率]

请按以下要求排查：

**排查顺序**：
- 先从[最可能的方向]入手，给出判断依据
- 每个假设都要说明「如果成立，应该观察到什么」

**取证要求**：
- [需要看哪些日志/寄存器/变量]
- [需要加什么临时打印，加在哪]

**禁止事项**：
- 禁止在未定位根因前直接改代码
- 禁止一次性改多处，改动必须可单独回滚

**输出格式要求**：
- 首先，列出可疑点并按可能性排序
- 然后，给出下一步验证动作（具体命令/代码）
- 最后，说明当前证据支持什么结论、还缺什么证据

**当前项目上下文**：
- 技术栈：[框架+工具]
- 相关文件：[路径]
- 已知约束：[如不能改 vendor 代码]

验证方式：[怎么确认修好了]
```

## 文档模板

写 README / 设计说明 / 注释时用。

```
你是一位[领域]技术文档工程师，擅长把[复杂概念]讲给[目标读者]。

你的任务是[明确要写哪份文档]。

请按照以下要求完成：

**读者假设**：
- 读者是[角色]，已具备[前置知识]，不需要[不需要解释的内容]

**结构要求**：
- [章节顺序]
- [每节长度上限]

**风格要求**：
- [语言：中文/英文]
- [语气：直述/教学]
- [术语表是否需要]

**禁止事项**：
- 禁止编造不存在的接口 / 参数 / 行为，不确定就标注「待确认」
- 禁止整段粘贴源码代替解释

**输出格式要求**：
- 首先，给出文档大纲
- 然后，输出完整正文
- 最后，列出文中「待确认」项清单

**当前项目上下文**：
- 技术栈：[框架+工具]
- 已有文档：[路径，避免重复]
- 代码来源：[关键文件路径]
```

## 数据分析模板

查数据、做统计、出结论时用。

```
你是一位[领域]数据分析师，擅长[分析方法]。

你的任务是[明确的分析目标]。

请按照以下要求完成：

**数据来源**：
- 数据位置：[路径/表名/接口]
- 字段含义：[关键字段说明]
- 数据质量已知问题：[缺失/重复/口径不一]

**分析要求**：
- 指标定义：[每个指标怎么算]
- 分组维度：[按什么切]
- 时间范围：[起止]

**禁止事项**：
- 禁止在指标定义不明时直接出结论
- 禁止用样本量不足的分组下判断

**输出格式要求**：
- 首先，说明数据口径与清洗动作
- 然后，给出分析结果（含样本量）
- 最后，给出结论与「结论不成立的条件」

**当前项目上下文**：
- 技术栈：[工具链]
- 已有分析：[避免重复]
```

## 逐节填写指南

| 节 | 填什么 | 常见坑 |
|----|--------|--------|
| 角色 | 「领域 + 手段」，如「车载嵌入式 C 专家，擅长 MISRA 风格改造」 | 写「资深工程师」等于没写 |
| 任务 | 一句话说清「做什么 + 做完长什么样」 | 把实现方案混进任务描述 |
| 规范要求 | 命名 / 注释 / 分层 / 类型约定，能引用已有文件就引用 | 写「代码要规范」 |
| 安全健壮性 | 输入校验、异常路径、资源释放、并发 | 泛泛写「注意安全」 |
| 领域要求 | 该领域的硬指标（性能 / 时序 / 协议） | 抄别的领域要求 |
| 禁止事项 | 越界行为、不许动的文件、不许引入的依赖 | 写「不要写烂代码」 |
| 输出格式 | 交付顺序 + 呈现形式 + 注释要求 | 不说要不要贴完整代码 |
| 项目上下文 | 技术栈 / 已有实现 / 可直接引用的代码片段 | 不查工程，凭想象写 |

> 领域要求这一节的标题本身就是占位符（`**[领域特定要求]**`），替换成实词，例如
> `**AUTOSAR 分层要求**`、`** EMIOS PWM 时序要求**`。
