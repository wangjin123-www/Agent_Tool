# 防漏校验：七维台账 + 双向核对

> 写方案**之前**做。校验不过 → 回分析阶段补，不进入写方案。
> 这是本 skill 存在的第一理由：移植漏一部分 = 目标工程编译过但功能残废，且极难排查。

## 核心规则：三态全覆盖

源侧每一项事实，处置有且只有三态：

1. **移植** —— 进方案 §四.A/B/C/D 某一行
2. **桩** —— 签名保留、实现为空，落点 = 源符号所属模块的目标对应文件（目标已有则追加进既有文件），进 §四.A/B 并标明
3. **明确不移植** —— 方案 §一/§六 写明理由（后续阶段/目标无硬件/SOC 交互暂缓）

出现第四态（没提到）= 漏。台账中不允许存在"未处置"行。

## 七个校验维度

| # | 维度 | 源侧事实来源 | 核对目标 | 漏掉的后果 |
|---|---|---|---|---|
| 1 | **文件级** | port_scan 文件清单 | 每文件有处置态 | 整块功能缺失 |
| 2 | **符号级** | 每个 .h 的 extern 函数/全局变量 | 目标有定义或桩（链接闭包） | 链接失败或静默缺函数 |
| 3 | **开关级** | 引用的每个配置宏 | 目标已有/新加/显式保持 OFF | 逻辑静默缺失（编译照样过） |
| 4 | **回调级** | 生成物硬耦合回调名、中断服务名 | 目标命名对齐或重生成对齐 | 链接失败/中断不触发 |
| 5 | **配置级** | mex 外设/时钟/链接脚本段 | §四.D 重生成项 or §四.C 手术项 | 上板外设不工作 |
| 6 | **调度级** | 任务周期/事件表槽位/分频/喂狗 | 接线项进 §四.C | 周期错 → 时序常量全体错 |
| 7 | **数据级** | 共享结构体/保留段字段 | 合并进目标对应结构体 | 运行期数据丢失/越界 |

可选第 8 维 **git 级**：用户给了 commit 汇总或源有清晰 git log 时，逐条 × 当前分支存在性。

## 台账格式

```markdown
| # | 维度 | 源侧事实 (file:line) | 处置 | 方案落点 | 备注 |
|---|---|---|---|---|---|
| 1 | 文件 | App_Power.c (1024行) | 移植 | §四.A 行1 | 替换占位 |
| 2 | 开关 | FUNC_STR_EN (Proj_Cfg.h:88) | 保持 OFF | §四.C | 决策#2 |
| 3 | 符号 | CanApp_GetXxx() (桩引用) | 桩 | §四.A 桩组 | 签名同源 |
```

台账放 `output/`（如 `output/port-ledger-<模块名>.md`），方案 §四 是台账的展开而非复制。

## 反向校验（防"过多改目标工程"）

方案定稿前，对 §四.C"修改既有文件"逐行追问：

1. 这一行**为什么非动不可**？（接线/开关/对齐——有源侧或板级依据）
2. 有没有更小改法？（融合点能否只加不改；开关能否代替改码）
3. 它溯源到台账哪一行？——**答不出台账行号的修改行，删。**

同时检查红线表：目标已有真实成果、生成物目录、源业务逻辑三类红线，
在 §四 各行中**一次都不允许被违反**。

## 校验通过判据

- [ ] 七维台账全满，无"未处置"行
- [ ] 台账每一行 → 方案有落点（或方案明确写"不移植+理由"）
- [ ] 方案 §四 每一行 ← 台账有行号（反向）
- [ ] 桩落点封闭：每个桩落在源符号对应模块文件内，无清单外"集中桩文件"
- [ ] 红线零违反
- [ ] git 级（如做）：commit 全覆盖，分支外补丁已标"可选增强"
