# Goal 格式：交互2（按方案移植）的执行约束

> 仅当用户明确要求执行（交互2）且方案已批准后，开始执行前输出 goal 块。
> 它是方案的"可执行摘要"，执行全程贴着它走；机械可判定的 Stop if 触发时立即停下报告，不自行变通。
> **goal 只从已批准方案推导，绝不在此阶段重新分析或扩大范围。**
>
> **方案来源**：交互1 批准的方案已落盘到 `output/<模块名>-port-plan.md`。
> 交互2 开始时先 `ls output/` 让用户指定方案文件（或用户直接给路径），读全文后
> 在 goal 块声明"目标方案 = <路径>"。找不到方案 → 停，回交互1。

## 模板

```
/goal <一句话描述目标：把<源模块>从<源工程>移植到<目标工程>，覆盖 N 文件/M 行，纯拷贝+K 个熔接面>
依据方案: <已批准方案文件路径>

Scope: <作用范围 — 改哪些目录/文件/子系统；明确写出"此外不要碰"。来自方案 §四 A/B/C/D 目标侧路径并集，不新增>

Constraints:
- 源业务逻辑一行不改：只做 include 层名替换与决定好的板级重算项
- <生成物目录>严禁手改，只走重生成 + git diff 审查
- <DLP/工具约束，如有：加密文件只 Edit/Write，严禁 sed/重定向/脚本批量替换>
- <时序常量对齐约束，如有：任务周期 X ms，配套宏必须按 X 标定>
- <决策表中的关键开关约束，如 FUNC_STR_EN 保持 0>

Done when:
1. <每步验证：编译命令 + 0 error、新增文件 0 warning>
2. <七维台账全过：output/port-ledger-<模块>.md 无未处置行>
3. <产物级：map/产物检查、符号齐全>
4. <上板级（如适用）：验证标准逐条>
5. <回归级：目标工程既有功能不受影响>

Stop if:
- 需要修改源业务逻辑才能编译通过
- 需要手改生成物目录才能继续
- 发现台账之外的源文件/依赖（方案未覆盖 → 停下补方案，不许顺手移植）
- 需要新依赖（新 RTD 基线/新工具链/新中间件）
- <目标工程红线文件必须被违反才能继续>

Use a token budget of <N> tokens for this goal.
```

## 从方案推导的规则

| goal 段 | 推导来源 | 纪律 |
|---|---|---|
| 一句话目标 | §一 源范围 + §三 熔接面数 | 含 N 文件/M 行量化 |
| Scope | §四.A/B/C/D 目标侧路径并集 | 写"此外不要碰"；不含纯读的源工程路径 |
| Constraints | §二 红线表 + 决策表 | 3-6 条，每条机械可判 |
| Done when | §五 各步验证 + §七 验证标准 | 每条引用具体文件名/命令，可打勾 |
| Stop if | §八 红线 + 台账外发现 | 全部机械可识别（编译错/目录名/文件发现） |
| token 预算 | 移植量 | 经验换算：每 1000 行移植量 ≈ 50k-100k；下限 200k；用户说过"宁多花 token"时取上限档 |

## 执行期纪律（goal 后继续执行时）

- 按方案 §五 步序执行，每步结束跑该步验证列，**过了才进下一步**。
- 每完成一步，对照 Done when 打勾进度；Stop if 命中 → 停，输出：触发了哪条 + 台账/方案差异 + 建议的方案修订，等用户裁决。
- 执行中所有对目标文件的修改走方案指定工具（DLP 文件 Edit/Write）。
- 全部 Done when 打勾后，输出总结：修改文件统计 + 验证结果 + 台账终表路径。
